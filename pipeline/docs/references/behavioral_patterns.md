# Behavioral Design Patterns

These patterns are specifically concerned with algorithms and the assignment of responsibilities between objects.

## 1. Command
Encapsulates a request as an object, thereby letting you parameterize clients with different requests and support undoable operations.

## 2. State
Allows an object to alter its behavior when its internal state changes. The object will appear to change its class.

## 3. Template Method
Defines the skeleton of an algorithm in an operation, deferring some steps to subclasses.

## 4. Memento
Allows capturing and externalizing an object's internal state so that the object can be restored to this state later.

## 5. Chain of Responsibility
Passes a request along a chain of handlers.

## 6. Interpreter
Evaluates a language grammar or expression.

## 7. Iterator
Accesses elements of a collection sequentially.

## 8. Mediator
Restricts direct communications between objects and forces them to collaborate via a mediator.

## 9. Observer
Notifies multiple objects about any events that happen to the object they’re observing.

## 10. Strategy
Defines a family of algorithms and makes them interchangeable.

## 11. Visitor
Separates an algorithm from the object structure on which it operates.
